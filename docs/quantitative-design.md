## 三、技术实现方案

### 3.1 核心: MetricsCollector 单例

创建一个轻量的采集器，作为所有打点的统一入口：

**位置**: `src/utils/metrics.js`（新建）
**功能**:
- 记录 API 调用的成功率、延迟、首字时间
- 记录文档解析的准确率、耗时、格式分布
- 记录简历生成的匹配度、用户编辑率
- 生成 JSON 报告，按天持久化到 localStorage

### 3.2 植入现有代码

| 文件 | 改动点 | 采集指标 |
|------|--------|----------|
| `src/api/deepseek.js` | streamChat/fetchWithRetry 中加入计时和计数 | API延迟/成功率/首字时间/重试率 |
| `src/utils/parser.js` | 解析前后加 timestamp，记录格式和结果 | 解析耗时/格式分布/失败率 |
| `src/stores/resume.js` | saveCurrent 时比对生成内容与保存内容 | 用户编辑率 |
| `src/router/index.js` | beforeEach/afterEach 计时 | 路由切换耗时 |
| `src/stores/share.js` | 增加 viewCount 字段和 increment 方法 | 分享访问量 |

### 3.3 借鉴 ResumeHQ 的双引擎评分设计

**现状**: jobMatcher.js 只做关键词匹配，返回纯文本分析。

**改进**: 引入双引擎匹配度评分：

```
匹配度评分 = 关键词Jaccard相似度(50%) + AI语义分析(50%)
```

- 关键词相似度：从 JD 和简历提取技能/经验关键词，计算交集/并集比
- AI语义分析：利用现有 DeepSeek analyzeJob 接口，输出0-100分
- 无需额外API调用即可获得量化数据

**最低可用版本**:

```javascript
export function calculateKeywordMatch(jdKeywords, resumeKeywords) {
  const intersection = jdKeywords.filter(k => resumeKeywords.includes(k));
  const union = [...new Set([...jdKeywords, ...resumeKeywords])];
  return union.length > 0 ? (intersection.length / union.length) * 100 : 0;
}
```

### 3.4 分享统计借鉴 JadeAI

**现状**: share.js 保存分享配置但无任何统计。

**改进**: 增加 viewCount 和 lastViewedAt 字段，每次查看 +1。

## 四、实施路线图

### 阶段一: 基础设施（1-2天）
1. 创建 `src/utils/metrics.js` MetricsCollector
2. 给 deepseek.js 加 API 延迟/成功率打点
3. 给 parser.js 加解析耗时/格式打点
4. 路由切换时间采集

**产出**: 后台数据持续采集，可输出 JSON 报告

### 阶段二: 关键指标落地（2-3天）
1. 简历生成匹配度双引擎评分
2. 用户编辑率跟踪
3. 分享查看统计
4. 文档解析准确率抽样测试

**产出**: 所有 P0/P1 指标可采集

### 阶段三: 可视化与持久化（1-2天）
1. Dashboard 添加系统状态卡片
2. 设置页添加"量化指标"面板
3. 日级别 localStorage 持久化

**产出**: 用户可见的量化面板，可导出报告
